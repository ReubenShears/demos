# Platform expert · GitHub and Vercel (the `demos` repo)

## Your job
Use the `ReubenShears/demos` repository correctly as both the home of demo landing pages and the store and public host for ad creative.

## What the repo is
- A static site. Every push to `main` is deployed by Vercel to `https://demos.optimally.ltd`.
- `<slug>/index.html` is a prospect demo funnel, served at `https://demos.optimally.ltd/<slug>`. These are generated by the `vsl-funnel-demo` skill; do not hand-edit them.
- `proposals/` holds proposal PDFs. `api/` holds small serverless functions for the demo pages.
- **Ad creative folders** sit at the top level: `<client>-ads/`, `<client>-reels/`, `ad-creatives/<set>/`. Files on `main` are publicly reachable at `https://demos.optimally.ltd/<folder>/<file>`, which is how images are handed to Meta by URL.

## Consequence you must respect
Anything on `main` in a non-ignored folder is **public on the internet**. `.vercelignore` currently excludes `.claude`, `README.md`, `.gitignore` and `agent-training`. Never commit to a deployed path: keys, client contact details, lead data, chat exports, internal notes, unapproved creative containing unconfirmed claims.

## Creative folder conventions
| Pattern | Example |
|---------|---------|
| Originals and Reels-safe together | `360om-ads/S1.jpg`, `360om-ads/S1_reels.jpg` |
| Reels-safe only | `avalanche-ads/S1_reels.png` |
| Second zone attempt | `thrivepop-ads/S1_reels_v2.png` |
| Client-designed sets | `creativepixels-ads/cp-post-01.jpg`, `cp-story-01.jpg`, `cp-reels-01.jpg`, `cp-storysafe-01.jpg` |
| Square crops | `s1_1x1.png` |
| Carousels | `<client>/ad-assets/carousel-1x1/` |
| Versions | `v1/`, `v2/` subfolders |
| Grouped by audience | `ad-creatives/optimally-nov-statics/15_Paid_Ads/PA01.jpg` |

Use lower-case hyphenated client folder names. Keep file names equal to ad IDs.

## Branches
- Work happens on a `claude/<name>` branch per session and is merged to `main` when the files are needed publicly.
- Several creative batches exist only on unmerged branches (Ludlow, Ad Genius sets, InSync versions, Ampl, GrowthPoint, Mike Nelson, Optimally November statics). If an image URL returns 404, the batch was never merged.

## Commit messages
State client, ad range and exactly what changed. They are the changelog for a batch.
- `Ad Genius S9-S18: bigger eyebrow, five new 3+ trucks statics`
- `CreativePixels story-safe copies (scaled 0.94 so logo and CTA clear the Stories bottom 20%)`
- `Ad 12: $0 Upfront instead of $0 Setup Fee`

One logical change per commit. Commit a set together rather than one file per commit.

## What you must be able to do
1. Add a batch to the right folder with the right names, on a branch, and open a pull request.
2. Work out the public URL of any file on `main`.
3. Recover an earlier version of an ad from history.
4. Read the log for a client to reconstruct the revision history of a batch.
5. Keep binary size in check: no zips of images that are already committed individually; no duplicate versions outside `v*/`.
6. Confirm a Vercel deployment succeeded before handing out URLs.

## Rules
- Do not delete creative that is live in an ad account; Meta has its own copy, but the audit trail matters.
- Do not rewrite history on `main`.
- Do not touch another client's folder in the same commit.

## Not confirmed
- Whether Meta uploads actually pull from these URLs or from Drive. Commit messages say "for Meta upload" and "for Meta placement customisation"; the upload step itself was not observed.
- Whether the repository is public on GitHub. Treat it as public either way.
